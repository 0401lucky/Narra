# v2.3 视觉回归安全网与基线核验

## Goal

在 v2.3 视觉迁移前，建立稳定发现回归的截图安全网，并确认当前版本可用的性能证据。保持现有产品外观和行为，为后续迁移提供可信对照。

## Background

- 父任务：[Narra 体验一致性路线图](../10-14-narra-experience-consistency/prd.md)，对应 R11、R12 及 R1–R3/R9 的前置证据。
- 用户已同意先安全网、再聊天/角色列表/扮演气泡试点的方向，并于 2026-10-14 授权创建任务。
- 当前 CI 有构建、JVM 单测和 Lint，无 Roborazzi/Robolectric 门禁；已有设备 UI 测试和截图取样可参考，但不等于严格基准图比较。
- 现有性能任务的真机 AC4/AC8 尚未验收。本任务核验与复用现有结果，不重建框架，也不以旧待办推断当前设备连接状态。

## Requirements

- S1：建立 15 个有源码依据的候选页面/容器清单，标明首批试点与后续扩面；普通 Chat 只作内部回归，不恢复入口。
- S2：首批聊天、角色列表、扮演气泡有确定性截图，覆盖深浅色、代表性空/长内容、窄屏和 200% 字体；气泡额外覆盖 13 套皮肤、背景/玻璃开关与自定义尺寸边界。
- S3：数据、日期、字体、设备参数、动画时刻、动态配色和本地图片可复现，不读取用户会话、凭据或网络图片。
- S4：固定环境的已覆盖用例出现 1px 差异时，验证任务非零退出并保存预期、实际、差异图；相同输入重跑稳定通过，缺失基准不得视为成功。
- S5：CI 增加截图验证并保留原有三项检查，失败仍上传诊断产物；不自动接受基准，初始基准与视觉变化均有人工确认记录。
- S6：登记性能证据并核对提交、真机、编译模式、数据、刷新率、动画缩放和温控条件；条件满足时补录现有场景，保留原始结果与来源。
- S7：明确宿主截图、设备视觉、系统栏/输入法/玻璃与真实性能的覆盖差异；缺真机或有效证据的项保持未验收，模拟器帧数据不能替代。

## Acceptance Criteria

- [ ] A1 / S1：覆盖矩阵列明 15 个有源码依据的候选界面，首批与后续范围可区分。
- [ ] A2 / S2–S3：首批固定用例连续两次验证通过，无真实数据、网络依赖或未等待的图片/动画状态。
- [ ] A3 / S4：故意注入 1px 差异和缺失基准使真实验证链路失败，恢复后通过；记录退出码与差异产物。
- [ ] A4 / S5：CI 新增截图门禁并保留构建/单测/Lint，失败产物可审阅，基准生成与验证分工明确。
- [ ] A5 / S2、S7：人工确认初始基准及代表性设备效果；宿主无法真实呈现的用例转入设备矩阵，不静默替换效果后声称覆盖。
- [ ] A6 / S6–S7：性能登记可核验，缺测和失效原因明确；条件具备时取得当前源码 S0–S3、F1–F3、N1 原始结果，无有效真机数据时本项保持未完成。
- [ ] A7：相关构建、JVM、Lint 与测试源码检查通过，产品入口、外观、自定义设置及发布配置无业务变化。

## Out of Scope

- 令牌替换、皮肤配色变化、无障碍布局修复、全 App 截图覆盖及实际体验功能开发。
- 性能框架重构、协议/存储/namespace/导航迁移、上传截图到外部截图服务、发包与更新清单修改。
- 一次性完成系统悬浮翻译、真实软键盘及所有硬件能力自动化；这些保留明确的设备验收项。

## Implementation Approval

2026-10-14 续做会话中，用户明确确认已审阅上一会话的最终规划，并批准按现有规划启动本子任务。PRD、design、implement 及两份 JSONL 已核对，路径校验通过（各 11 条真实上下文条目）。仅启动本子任务，父任务及令牌试点维持原状态。

当前范围没有未决产品选择：只建立现状证据与门禁。技术接入先做最小兼容性验证，不能据此降低 S4/S5 或改变产品行为。初始基准人工确认、设备与性能验收独立记录；批准实施不代表这些验收已经通过。
