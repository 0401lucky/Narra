# 单条消息删除功能

## Goal

为 2.2.5-dev 提供普通聊天与角色扮演（RP）共用的单条消息删除能力。用户可在
消息菜单中经过二次确认后，独立、不可逆地物理删除目标消息，并同步清理会使后续
上下文失真的直接关联数据。

## User value

- 用户可以移除误发、无效或不希望继续保留的单条内容，而无需清空整个会话。
- 删除后的消息、记忆、摘要和引用状态保持一致，不会在重新进入会话后复现。
- RP 现有“撤回”语义继续保留，用户可明确区分“保留撤回痕迹”和“彻底删除”。

## Confirmed facts

- 普通聊天消息操作面板位于 `ChatMessageWorkUnitSheets.kt:79-229`，当前没有删除
  回调；消息回调集合也没有删除项（`ChatScreenCallbacks.kt:17-29`）。
- RP 长按菜单位于 `RoleplayMessageBubbles.kt:645-742`，已有复制、编辑、引用、
  撤回和重回回合，但没有删除；撤回由
  `ConversationRepository.kt:326-356` 保留消息行并改写为撤回事件。
- 普通聊天与 RP 都持久化为同一 `ChatMessage` / `messages` 表。一个 RP 底层消息
  可映射成多个 UI 气泡（`RoleplayMessageUiMapper.kt:230-280`），因此删除单位必须是
  底层 `sourceMessageId`，不能只移除某个派生气泡。
- 当前 `ConversationStore` 没有单条删除契约（`ConversationStore.kt:7-48`）；
  `RoomConversationStore.updateConversationMessages` 只 upsert 新增或变化消息，无法
  持久化列表中的删除（`RoomConversationStore.kt:86-105,249-256`）。
- `MessageEntity` 同时保存顶层引用和序列化消息分段
  （`MessageEntity.kt:33-37`）；来源记忆通过 `sourceMessageId` 关联
  （`ChatMessageMemoryCoordinator.kt:61-82`）；摘要分段记录消息边界和数量
  （`ConversationSummaryCoordinator.kt:135-178`）。

## Requirements

### R1. 双入口与独立语义

- 普通聊天与 RP 的所有消息展示模式都提供“删除”入口。
- 删除与 RP “撤回”并存，互不替换：撤回保留消息行和撤回痕迹；删除移除消息行。
- RP 的删除目标始终使用底层 `sourceMessageId`，同一来源生成的多个 UI 气泡一起消失。

### R2. 二次确认与并发保护

- 删除前必须展示明确的不可逆确认提示；取消确认不产生任何写入。
- 发送或流式生成期间，以及目标消息状态为 `LOADING` 时，不允许发起删除。
- ViewModel 必须在执行时再次校验当前会话、目标消息和发送状态，不能只依赖 UI
  隐藏或禁用。

### R3. 物理删除与幂等性

- 确认后从 Room `messages` 表物理删除目标消息，重新观察、切换页面或重启应用后
  均不得恢复。
- 目标消息不存在时返回幂等 `NotFound/NoOp`，不报错、不误删其他数据。
- 保留会话标题、模型、其他消息的顺序和非关联内容；只允许刷新会话 `updatedAt`。

### R4. 原子关联清理

以下操作必须处于同一个 Room 事务，任一步失败都整体回滚：

1. 删除目标消息行。
2. 删除所有 `sourceMessageId == targetMessageId` 的 `memory_entries`，覆盖全局、
   角色和会话作用域。
3. 删除目标会话的总摘要及全部摘要分段。
4. 清除同会话其他消息中指向目标消息的引用，包括顶层
   `replyToMessageId/replyToPreview/replyToSpeakerName`，以及 `partsJson` 内每个消息
   分段的同名字段。

### R5. UI 与派生状态一致性

- 删除成功后通过现有 Flow 更新普通聊天消息列表、RP 原始消息及派生气泡。
- RP 当前输入若正在引用目标消息，删除成功后清空本地引用草稿。
- 普通聊天的 `rememberedMessageIds`、摘要状态，以及 RP 上下文状态必须随底层关联
  数据删除而更新，不保留幽灵状态。
- 删除失败时保留原消息和所有关联数据，并使用现有安全中文错误提示；不得暴露路径、
  SQL、堆栈或聊天正文。

### R6. 附件策略

- 删除消息行会移除其附件 URI/元数据引用，但本版本不删除 URI 指向的本地文件、
  相册内容或外部文档。
- 不新增文件垃圾回收、引用计数或附件生命周期管理。

### R7. 兼容性

- 本任务只新增 DAO 查询和事务逻辑，不修改 Room Entity、字段、索引或数据库版本。
- 不新增远端删除接口；当前消息数据以本地 Room 为唯一持久化事实来源。

## Acceptance Criteria

- [ ] **AC1（R1、R2）**：普通聊天、RP 离线模式和 RP 在线模式均可从消息菜单打开
      删除确认；取消后消息和关联数据完全不变，RP 撤回入口仍可独立使用。
- [ ] **AC2（R3）**：确认后仅目标底层消息从 UI、Room、重新观察和重新进入会话结果
      中消失；目标不存在时幂等返回，其他消息顺序、内容、会话标题和模型不变。
- [ ] **AC3（R4）**：删除成功后，其他消息顶层及分段内指向目标的全部 `replyTo*`
      字段被清空，未指向目标的引用保持不变。
- [ ] **AC4（R4、R5）**：所有以目标消息为 `sourceMessageId` 的记忆被删除；目标会话
      总摘要与全部摘要分段被删除；相关观察 Flow 不再报告已记忆或已摘要状态。
- [ ] **AC5（R1、R5）**：一个 RP 底层消息映射出的多个气泡会一起消失；若输入框正在
      引用该消息则引用草稿被清空，删除其他消息不影响当前引用。
- [ ] **AC6（R6）**：删除带图片或文件附件的消息后消息记录消失，但对应本地测试文件
      仍存在，删除路径不调用文件清理能力。
- [ ] **AC7（R2、R5）**：发送中、流式中或 `LOADING` 消息无法删除；并发状态变化不会
      让已删除消息被迟到写入重新插回，也不会留下永久 loading。
- [ ] **AC8（R4、R5）**：事务任一步失败时消息、引用、记忆和摘要全部保持删除前状态，
      UI 显示脱敏错误；成功后不出现“消息已删但关联清理失败”的部分成功状态。
- [ ] **AC9（R1-R7）**：纯逻辑、Repository/Store、ChatViewModel、RoleplayViewModel、
      Compose/设备测试与项目质量门禁全部通过；确认无 Room schema 版本变化。

## Out of scope

- 批量删除、按时间段删除、删除整段回合、删除整个会话。
- 回收站、撤销删除、云端同步删除和跨设备同步。
- 删除单个 RP 派生气泡而保留同一底层消息的其他气泡。
- 自动重新生成摘要；删除后摘要保持为空，后续按现有触发规则重新生成。
- 删除附件实体文件、附件垃圾回收和磁盘空间治理。
- 改变 RP 撤回、编辑后重发或重回回合的现有语义。
- 选择性清理没有 `sourceMessageId` 关联的待确认记忆提案或历史记录。

## Final decisions

- 普通聊天和 RP 均支持独立、不可逆的物理删除。
- RP 撤回继续保留为不同操作。
- 消息、引用、来源记忆、总摘要和摘要分段采用同一 Room 事务原子清理。
- 本版本不删除本地附件文件，不修改 Room schema，无阻塞开放问题。
