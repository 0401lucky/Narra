# v2.4.1 陪伴 D2：三种开场与上下文衔接

## 目标与归属

在现有角色/线下流程内完成可接受的三开场、输入与留白继续，让同一关系在媒介切换和日常会话之间正确延续。

父任务为 [完整陪伴升级](../11-09-date-companion/prd.md)，版本固定2.4.1，承接 N1、N3、N4；AC1/AC4/AC5/AC6。用户已确认升级现有线下扮演和完整规划；完整方案已于2026-11-09获实施批准；按前置依赖由主会话激活，当前状态见task.json。

## 前置与边界

前置：[D1](../11-09-date-companion-foundation/prd.md) 已通过独立验收并提供对应接口/验证证据。父任务的记忆/身份/版本/入口/范围外条款同样适用；依赖不由任务树顺序隐含。

## 需求

- **D2-R1**：保留打开旧会话，显式新场进入准备；从线上返回原scenario/conversation/mode，记忆用途不变。
- **D2-R2**：我靠近/角色靠近只生成预览，接受后正式入经历；直接开始零开场请求并跳过新路径的静态greeting seed。
- **D2-R3**：统一INPUT/CONTINUE/OPENING输入转换与用户执笔规则，重试/重生成保持原语义；不无条件带入线上手机/经济/脚本规则。
- **D2-R4**：建立授权原文scope：同会话媒介转译、CONTINUOUS同角色/persona允许原文聚合，INDEPENDENT/群私有/断点/空范围隔离。
- **D2-R5**：每个入口独立准备记忆/世界书与最终请求回执；提示定位真实user，不污染检索关键词或深度。
- **D2-R6**：沿用场景现实时间开关，支持可选角色ZoneId；关闭时统一抑制额外实时包装，不改变原文、真实时间戳或记忆用途。

## 验收标准

- [x] **D2-AC1**：新建/旧会话/新场/重开各自行为正确；开场预览多次废弃无消息/提取，连点接受一次，直接开始零请求。
- [x] **D2-AC2**：准备/设置/阅读/恢复导航不自动生成，A离场开B后A响应不改变B，准确返回原线上会话。
- [x] **D2-AC3**：继续发送/失败重试/reroll的最终HTTP语义一致，技术长文不进原文/来源。
- [x] **D2-AC4**：最终HTTP覆盖角色/persona/独立/群私有/空授权/断点/删源竞态；日常新鲜跨会话原文可见且不等待提取。
- [x] **D2-AC5**：记忆关闭/失败无旧注入，相同depth/depth0世界书顺序role正确，四类时间/跨时区场景可复现。
