# 2.2.12-dev 设计汇总

## 已确认的行为

- 线上聊天新增全局开关，默认开启；关闭后保留背景图并使用所选主题气泡。
- 线下聊天与无背景聊天沿用现有表现。
- 朋友圈时间线评论预览恢复紧凑布局，单击与长按操作继续可用。

## 设计分工

| 子任务 | 设计与边界 | 与另一子任务的依赖 |
| --- | --- | --- |
| R1 | [线上气泡设计](../09-08-online-background-bubbles/design.md)：主题配置持久化、设置入口、消息配色 / 材质 / 形状 / 宽度 | 无 |
| R2 | [评论间距设计](../09-08-moments-comment-spacing/design.md)：仅调整时间线评论预览的布局和对应设备测试 | 无 |

两项可分别验收、分别回退。父任务集中维护版本记录，避免不同执行者同时编辑发版文档。

## 跨层契约

R1 复用现有主题对象与设置保存链路：设置 UI → SettingsViewModel 草稿 → SettingsPersistenceCoordinator → AiSettingsEditor → AppSettingsStore → settingsFlow → 线上消息视图。

新增字段位于既有主题 JSON 中，旧配置缺失字段时开启。无需 Room schema、角色数据迁移、权限或网络改动。设置范围为全局，但渲染判断必须以 ONLINE_PHONE 模式为边界。

R2 不进入 ViewModel / Repository，不变更评论数据；仅影响时间线中最多四条评论的预览布局。

## 兼容性与验收重点

- R1 必须同时处理配色、形状、宽度和实际渲染外壳，不能仅修改透明度。
- 真实背景状态继续负责图片展示、系统栏和页面控件；消息使用独立派生的视觉状态，禁止通过清空背景状态模拟关闭玻璃。
- R2 只移除评论预览的显式大行高，不改变全应用 48dp 触控标准；验证相邻评论的点按及长按命中。
- 默认开启保持现有有背景聊天的初始效果；用户主动关闭后才进入主题气泡路径。
- 主题自身的透明配色保持原样，例如所选液态玻璃主题不会被强行改成纯色。

## 验证与回退

验证按 [implement.md](implement.md) 执行，包括配置兼容、保存失败、视觉状态组合、评论布局和手势。规划阶段仅检查文档、上下文清单及引用有效性，不把计划中的测试记为通过。

两项按文件边界独立回退。R1 若需撤回可还原该功能的模型 / 解码 / UI 变更，旧版本会忽略新增 JSON 字段；不清空用户设置。R2 可局部还原预览布局和对应测试。当前设计不包含构建上传或更新源发布。
