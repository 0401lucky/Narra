# UI 重设计技术设计

## 设计目标

建立一套可复用的 Compose 视觉基础，逐阶段替换现有页面的壳层、组件和信息层级。设计优先保证舒适、清晰和可持续使用，再保留 Narra 的角色陪伴感。

## 视觉基础

- 以现有 Material 3 `ColorScheme` 为兼容入口，统一语义色、表面层级、边框、状态色和深浅色映射。
- 在 `ui/theme/` 集中维护间距、圆角、控件高度、图标尺寸、内容最大宽度和层级间距；页面不再散落自定义数值。
- 采用克制、温和、有轻微个性化的现代移动端风格：减少厚重卡片和装饰性渐变，保留少量品牌强调色。
- 图标按语义和线条风格统一；底部导航、列表入口、操作按钮、状态标记分别定义图标尺寸和选中态。
- 交互表面优先使用清楚的层级、留白和状态变化，不依赖阴影或大面积玻璃效果表达结构。

## 信息架构

- 列表行默认显示标题、短状态或一句摘要；较长的技术说明移入可展开帮助、信息图标或独立高级设置区域。
- 用户操作相关提示与实现细节分离；接口路径、占位符、兼容规则、调试输出不与普通设置项抢占同一视觉层级。
- 对重复的 section、list row、setting card、help disclosure、status pill、empty/error state 建立共享 Composable，页面只提供语义内容。
- 保留现有导航和数据契约，先改表现层；如需改变交互语义或数据保存行为，单独记录迁移和回滚方案。

## 分阶段边界

1. 视觉令牌、通用壳、导航、弹层，及 `ImmersivePhoneShell` 四个 Tab，重点是 Profile。
2. Roleplay 主流程、设置侧栏、手机/邮箱/钱包/日记/阅读/视频等子页。
3. Settings 全深层页，按 Provider、Assistant、Data、Voice、Diagnostics 等域收敛。
4. Home、Moments、PhoneCheck 等仍可从产品入口访问的页面。
5. 系统悬浮翻译、跨页面 Dialog/Sheet 收口和全 App 回归。

当前 `AppRoot.kt` 从 `ROLEPLAY_GRAPH` 进入；`AppNavHost.kt` 仅在基准测试会话中注册普通 Chat 与独立 Translator。它们的源码仍在仓库，但不属于本次日常产品 UI 改造范围，也不恢复产品入口。共享消息组件只有实际被角色扮演页面使用时才按需调整。

用户已确认保留 Telegram 风格的悬浮底部导航，“我”页面不再重复显示顶部标题。场景主题、气泡预设、背景和立绘属于用户定制能力，不能以统一视觉为由覆盖。

## 兼容与风险

- 主题选择、深浅色、角色背景和用户头像等现有能力必须继续工作。
- 大量页面共享 `MaterialTheme`，修改 tokens 可能造成全局回归；每阶段需截图和构建验证。
- 悬浮翻译不在 Compose 导航内，需要单独验证权限、服务生命周期和面板状态。
- 长文本收起后必须提供可达的完整说明，不能以视觉简化为由删除配置语义。
