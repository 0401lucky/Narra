# 整体 UI 与个人页面重设计

## 目标

重新设计 Narra 整个 App 的可见界面，改善用户认为不好看、看着不舒服及图标不协调的问题，重点改善“我”页面。最终各页面应形成一致、舒适、易于辨认和操作的视觉体验。

## 当前事实

- 应用使用 Kotlin、Jetpack Compose 和 Material 3。
- `ImmersivePhoneShell.kt` 定义消息、通讯录、发现、我四个主标签，导航已使用 Lucide 图标，文件内仍混用 Material 实心图标。
- `ImmersiveProfilePage` 承载“我”页面，包含个人资料、默认面具切换、资料库和应用入口。
- `ChatAppTheme.kt` 支持抹茶、香草和海洋三套配色及深浅色模式。
- 页面之外还有底部面板、菜单、弹窗、输入栏、消息展示、图片预览和系统悬浮界面，需要按实际入口继续清点。
- 清点结果以当前产品入口为准：沉浸式手机壳和 Profile；Roleplay 全流程及其子页；Settings 深层页；Moments/PhoneCheck；系统悬浮翻译。普通 Chat 路由目前只在基准测试场景注册，不作为日常产品 UI 阶段。

## 需求

- R1 全面覆盖：所有现有可见界面及其弹窗、菜单、底部面板进入覆盖清单，逐项记录设计、实现、验证状态。
- R2 统一视觉：颜色、排版、间距、图标线条与尺寸、按钮、列表、输入框和反馈状态形成一致规则，同时让不同用途页面具有清楚的内容层级。
- R3 优先改善“我”：整理身份展示、面具切换、资料库及应用入口的布局和视觉主次，保证入口可发现、身份切换可理解。
- R4 完整界面状态：覆盖空白、加载、错误、禁用、选中等实际状态。
- R5 分阶段交付：每阶段有可运行成果与覆盖清单，最终进行全 App 一致性验收。
- R6 功能连续性：现有会话、角色、配置及资料操作保持可用；功能语义或用户数据变更需单独说明。
- R7 信息层级：默认收起大部分技术说明，只在主要操作附近保留一句简短提示；完整规则通过信息图标或“了解更多”查看；调试和实现细节仅在高级设置、诊断页或调试状态中出现。

## 阶段范围建议

- 阶段 1：设计令牌、通用壳/导航/弹层，沉浸式手机四 Tab，重点完成“我”。
- 阶段 2：Roleplay 主流程、侧边栏及手机、邮箱、钱包、日记、视频通话等子页。
- 阶段 3：Settings 全深层页，按 Provider、Assistant、Data、Voice 等域验收。
- 阶段 4：Moments、PhoneCheck 及独立页面。
- 阶段 5：系统悬浮翻译层、全局 Dialog/Sheet 统一和全 App 回归验收。

## 暂定边界

- 聚焦视觉与交互重设计，不主动扩大到新玩法、模型协议、数据存储重构或正式发版。
- 现有主题选择、背景定制与角色展示的兼容方案需在设计中明确，不能静默删除已有能力。
- App 启动图标是否随应用内图标一起更换，纳入后续品牌范围确认。
